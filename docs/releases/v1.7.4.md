# PG-Limiter v1.7.4

Release date: 2026-11-05.

Named Mirza Bot instances share notification settings across selected PasarGuard
admins.

## Changes

- **Shared bot settings:** Settings → Notifications groups the API URL, key,
  message and punishment triggers under each named Mirza Bot. Select admins
  directly from the full panel list using Include-only checkmarks; manual admin
  entry is removed. Each admin can belong to only one bot, including disabled
  bots. New bots start disabled with no admins.
- **Selection and edits:** Refresh reloads the panel list. Saved members remain
  removable when the panel is unavailable. Unselected and newly created panel
  admins receive no notifications. Editing settings or membership cancels the
  bot's older unsent events; requests already in flight may complete.
- **Preserved configuration:** Migration `013_notification_bots` turns each
  existing per-admin configuration into one bot containing its original admin.
  IDs, revisions, credentials, settings, enabled states and delivery history are
  preserved. Previously queued single-admin events remain supported. Matching
  URLs do not merge bots, and historical punishments are not backfilled or replayed.

## Upgrade from 1.7.3

1. Retain a complete private backup, including the database and state sidecars:

   ```bash
   sudo pg-limiter backup /root/pg-limiter-before-1.7.4.zip
   ```

   Also retain the 1.7.3 image tag/digest, Compose file and management script.
   The updater's partial file copies do not replace this archive. Backups contain
   API keys and must remain private.
2. Keep the existing panel credentials, TLS setting and persistent mounts. The
   panel key needs `admins.read` for selection and appropriately scoped
   `users.read` for included admins. No new environment setting is required.
3. For an ordinary installation using the default paths and mounts, run:

   ```bash
   sudo pg-limiter update
   ```

   The updater refreshes its management script from `main` and installs that
   script's version; this command does not lock the target to 1.7.4. It also
   regenerates Compose with default mounts. For a fixed 1.7.4 deployment, custom
   paths/mounts or a private trial, use the recorded deployment procedure and
   retained Compose configuration with image
   `ghcr.io/javadmoqaddam/pg-limiter:1.7.4` instead of the generic updater.

   Startup applies migration `013`. Local Python installations continue to use
   Python 3.15 and run `python -m alembic upgrade head` against their configured
   `DATABASE_URL` before starting. Review the migrated bots and their admins in
   Settings → Notifications; see the [notification guide](../MIRZA_NOTIFICATIONS.md).

## Rollback

Version 1.7.3 cannot read revision `013` or grouped notification contexts in
SQLite and the punishment-fact journal. Revision `013` refuses **every in-place
downgrade**, including empty and single-admin configurations. Rollback requires
the full pre-upgrade database and state backup.

Stop the service and retain a separate copy of current data. While the 1.7.4
management script, image and restore helper are still configured, restore offline:

```bash
sudo pg-limiter stop
sudo pg-limiter restore /root/pg-limiter-before-1.7.4.zip
```

Confirm applying the archive, then answer **`n`** to **“Start the service now?”**.
Restore the retained 1.7.3 Compose file, image identity and matching management
script, verify the original persistent mounts, then start with `sudo pg-limiter
start`. Restoring the snapshot discards later configuration changes and receipts;
restored pending notifications may repeat messages sent after the backup.

Release image: `ghcr.io/javadmoqaddam/pg-limiter:1.7.4`
for amd64 and arm64. See [Backup & Restore](../BACKUP_RESTORE.md) and
[panel API-key migration](../PANEL_API_KEY.md) for upgrades from 1.7.0.
