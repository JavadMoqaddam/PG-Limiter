# PG-Limiter v1.7.0

Release date: 2026-10-25

PG-Limiter v1.7.0 adds node-based limits and private daily ban summaries, with more reliable monitoring, management and recovery.

- **Per Node counting works with Logs and API.** Each user's distinct eligible active nodes count once, regardless of how many IPs or inbounds they use on a node. Unknown node evidence preserves warnings and pauses affected enforcement; there is no IP-count fallback. **Per Inbound** counting is also available with Logs.
- **Daily Report summarizes actual bans.** Configure its forum topic to receive the previous calendar day's totals at **00:00 using the current environment `TZ`**. Counts use the punishment step actually applied, show plain bans separately, and count each user once in the total. Warnings and failed disables are excluded; reports contain no usernames or IPs. Delivery receipts protect against replay after restart.
- **Monitoring handles incomplete evidence and changing settings more reliably.** API Last seen is configurable, optional automatic fallback switches to Logs after two unsuccessful API cycles, and log reconnects preserve source timestamps. Overlapping CDN observations no longer inflate counts.
- **Settings and enforcement agree across Telegram, CLI and API.** Current limits, whitelist, groups, administrators and country policy are checked before punishment. Unavailable facts or superseded settings retain existing warnings rather than starting an unsupported action.
- **Telegram controls and reports are more dependable.** Replies belong to the active prompt, forum destinations remain consistent, and Status & Reports combines private aggregate health information. Topics pause stops new observational reports/history work; already-started punishment and critical notifications retain their completion guarantees through cancellation.
- **Backup and recovery are safer.** SQLite backups include committed WAL data, Telegram restores validate and stage uploads for offline application, legacy imports run only once, and automatic recovery uses the recorded disable incident. Actual disable history survives warning cleanup; ordinary scans and history reports no longer request ISP details. Startup tolerates temporary Telegram outages.

## Upgrade notes

- Back up before upgrading and update the management script and application image together. Startup migrates the configured SQLite database to **`011_daily_reports`**, including disable provenance and daily reporting. New backups use **format v2**; valid v1 backups remain supported. Apply staged restores with `pg-limiter restore FILE` while the service is stopped.
- Run **one limiter daemon per database**.
- Set `TZ` to the reporting timezone, such as `Europe/Berlin`; unset means UTC. An invalid explicit zone pauses Daily Report and emits a service diagnostic. Restart the process or recreate its container after editing deployment `.env`; log-source timezone settings do not set the reporting calendar.
- Existing `/16` subnet grouping becomes `/24`. Per Inbound requires Logs; select Per Device, Per IP or Per Node before switching to API. API accounts need `nodes:stats` permission.


## Install

Use the installer from this release:

```bash
sudo bash <(curl -fsSL https://raw.githubusercontent.com/JavadMoqaddam/PG-Limiter/v1.7.0/pg-limiter.sh) install
```

Docker images: `ghcr.io/javadmoqaddam/pg-limiter:1.7.0` and `:latest`, for amd64 and arm64.
