# PG-Limiter v1.7.2

Release date: 2026-10-30.

A small maintenance update for API monitoring: finish enforcement before user
sync starts, and report aggregate lookup timings to explain slow collection.

## Changes

- Keep one workload turn through API collection, enforcement and required
  pre-punishment IP refreshes. A waiting full user sync starts after the active
  cycle finishes. Due sync still has priority before the next collection, and
  actual policy changes still invalidate outdated evidence. This includes PR #46.
- Add elapsed time, average completed lookups per second and mean/p95/maximum
  lookup duration to the existing progress messages. Individual request details
  stay at DEBUG. Metrics are local to each batch, include failures/timeouts and
  exclude unsent or cancelled calls. They add no panel requests.

These timings include the client's API call and response parsing; they do not
separate panel, node and network waiting. This update does not automatically
increase concurrency or eliminate the cost of per-user IP retrieval or full sync.

## Upgrade from 1.7.1

No environment-template update, new setting or database schema migration is
required. Keep the existing `PANEL_API_KEY`, TLS choice, concurrency, timeouts,
warning thresholds and Trust settings. Existing warning/history data is retained.

For an ordinary installed deployment, after this release and its image are
published:

```bash
curl -fsSL https://raw.githubusercontent.com/JavadMoqaddam/PG-Limiter/v1.7.2/pg-limiter.sh -o /tmp/pg-limiter-v1.7.2.sh
sudo bash /tmp/pg-limiter-v1.7.2.sh update
```

The updater stops the service for a database copy and retains configuration and
Compose backups. Keep the previous `1.7.1` image and its matching Compose file for
rollback. An active private trial must use its recorded upgrade/rollback path
with the same persistent mounts instead of the ordinary installed updater.

Release image: `ghcr.io/javadmoqaddam/pg-limiter:1.7.2` for amd64 and arm64.
Upgrading from 1.7.0 also requires the [panel API-key migration](../PANEL_API_KEY.md).
See [API diagnostics](../API_IP_SOURCE.md) for metric interpretation.
