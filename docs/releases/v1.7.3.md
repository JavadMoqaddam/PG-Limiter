# PG-Limiter v1.7.3

Release date: 2026-11-05.

Per-admin Mirza Bot punishment notifications, clearer Telegram delivery behavior,
unified backup controls, and a Python 3.15 runtime.

## Changes

- **Mirza Bot notifications:** Settings → Notifications lets each PasarGuard admin
  have a separate Mirza Bot API URL, key and message template. Choose the dynamic
  final punishment stage or specific stages. Each newly applied matching
  punishment can notify the customer identified by the numeric first field of
  the configuration note. `[Username]` inserts the configuration name and
  `[Limit]` its effective connection allowance. New routes start disabled.
- **Delivery handling:** Mirza Bot delivery runs independently of enforcement with
  persisted incident identity. Definite temporary failures have bounded retries;
  ambiguous sends remain uncertain. Critical Telegram notices retain durable
  retries, which can still duplicate a message after a lost acknowledgement.
  Noncritical uncertain sends are not blindly repeated, and newer complete
  warning scans supersede older unsent warning chunks.
- **Telegram updates:** Coalesce node summaries while a send is pending, preserve
  receipt ownership and retire producers during shutdown. Replace unavailable
  menus/status messages only after definite rejection. Preserve successful
  backup delivery when local cleanup fails.
- **Backup & Restore:** Move backup scheduling, Backup Now and Restore under
  Settings → Backup & Restore. Remove the unused direct-chat `/backup` feature.
  Immediate and scheduled backups use the configured backup topic and the
  established administrator fallback rules. Restore is available when scheduling
  is disabled; Backup Now follows the existing Auto-Backup enabled state.
- **Runtime and dependencies:** Use Python 3.15.0 in the container and Python 3.15
  for CI tests, lint and migrations. Update cachetools to 7.2.8, FastAPI to 0.162.0,
  Ruff to 0.17.3, pytest minimum to 9.2.0, pytest-asyncio minimum to 1.4.1.post1,
  and docker/login-action to 4.7.0.
- **Image validation:** Run offline dependency, version, migration and CLI checks
  on both candidate architectures before promoting the version and latest tags.

The notification feature preserves configured connection limits, counting rules
and punishment stage durations.

## Upgrade from 1.7.2

1. Create and retain a **complete private backup** before upgrading:

   ```bash
   sudo pg-limiter backup /root/pg-limiter-before-1.7.3.zip
   ```

   Keep the previous image tag/digest, management script and Compose file too.
   The updater's limited automatic file copies are not a substitute for this
   archive, especially with custom database paths and state sidecars.
2. Keep the existing `PANEL_API_KEY`, intended TLS verification setting, mounts,
   warning thresholds and Trust settings. No new environment setting is required.
3. After release publication, update an ordinary installed deployment with the
   versioned script:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/JavadMoqaddam/PG-Limiter/v1.7.3/pg-limiter.sh -o /tmp/pg-limiter-v1.7.3.sh
   sudo bash /tmp/pg-limiter-v1.7.3.sh update
   ```

   A private trial must use its recorded deployment path and persistent mounts.
4. Startup applies migration `012_mirza_notifications`, adding route/delivery
   tables and extending punishment evidence. Existing events are not backfilled.
   Local Python installations use Python 3.15 and run `python -m alembic upgrade
   head` against their configured `DATABASE_URL` before starting.
5. Configure and explicitly enable desired Mirza Bot routes using the
   [notification guide](../MIRZA_NOTIFICATIONS.md). API credentials and delivery
   state are stored in SQLite and included in backups; keep archives private.

## Rollback

Stop the service and retain a separate copy of current data before rollback.
Starting a 1.7.2 image against schema `012` fails because its Alembic code does not
know that revision. Merely changing an image tag is insufficient.

Using the current 1.7.3 management script and restore helper, apply the complete
pre-upgrade archive offline:

```bash
sudo pg-limiter restore /root/pg-limiter-before-1.7.3.zip
```

**Decline the restart prompt.** The archive restores the compatible database,
configuration and recorded state sidecars. Restore the retained 1.7.2 Compose
file/image identity and matching management script, verify the same persistent
mounts, then start the previous release. This restores the snapshot point; later
configuration changes and notification receipts are not retained. Restored
pending notifications can repeat messages sent after that snapshot.

An intentional `alembic downgrade` of revision `012` drops Mirza Bot settings, API
keys, delivery history and added evidence columns. It does not restore all
cross-file state and is not a substitute for restoring the pre-upgrade snapshot.
