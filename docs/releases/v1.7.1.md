# PG-Limiter v1.7.1

PG-Limiter 1.7.1 improves SSE recovery and API collection on changing user populations. Online-IP collection reports concise progress and successful-lookup percentages.

## Changes

- SSE gaps retire affected node evidence and recover through the existing warm-up. Original source timestamps and replay protection remain in effect, including during slow preparation.
- API evidence is scoped to each user's groups and effective node cores. Unrelated nodes no longer make every user's connection evidence unknown.
- Omitted per-user node maps no longer discard valid IPs from other nodes or trigger fallback by themselves. Successful responses use normal counting and warning clearing even when some or all node maps are omitted. No separate partial-response counting rule is used.
- Each API response retains its own observation window. Xray 26.4.13+ live connection maps include long-lived open connections; older/unknown Xray and WireGuard retain activity-time filtering. Stale punishment observations are fetched again before an action.
- Changing totals across valid user-list pages no longer discard every observed user. Missing candidates keep their warnings when pagination changes; background sync refreshes returned users and defers membership deletion. Invalid pages, conflicting identities and rejected credentials remain failures.
- Normal online collection logs show bounded progress and a final success percentage, with not-found, forbidden and failed lookups counted separately. Individual HTTP details are available at DEBUG.
- User-page requests run one at a time with a one-second pause after each response or error, including retries and background sync. Final membership checks use batches of scanned IDs independently of online status.
- Brief online-stat outages hold queued work for bounded recovery through a single probe. Unsent requests and timeouts are reported separately; coverage still excludes unknown users.
- Breaker recovery waits up to 65 seconds independently of observation freshness. The default IP timeout is 20 seconds, with saved overrides retained. Diagnostics include effective request settings and read/connect/pool/write timeout counts.
- The container supervisor forwards shutdown signals promptly and waits for Python cleanup instead of deferring the signal while Python runs in the foreground.

## Required credential migration from 1.7.0

Version 1.7.1 uses `PANEL_API_KEY` as its only panel credential. Configure the full key in `/etc/opt/pg-limiter/.env` **before upgrading**. `PANEL_USERNAME` and `PANEL_PASSWORD` no longer provide panel access. The optional limiter management API retains its own separate credentials.

For API collection, the key needs `nodes.read`, `nodes.stats`, `groups.read`, `cores.read` and appropriately scoped `users.read`. SSE/fallback also needs `nodes.logs`; configured punishment actions require their own permissions. Follow the [panel API-key guide](../PANEL_API_KEY.md) for the complete permission table, TLS settings and key rotation.

Take a backup before upgrading and retain the previous image for rollback. Keep the installer and image on the same version. This release adds no schema revision beyond `011_daily_reports`; it does not require resetting settings, warnings, Trust or history.

For an ordinary installed deployment, after configuring the key and after this release is published:

```bash
curl -fsSL https://raw.githubusercontent.com/JavadMoqaddam/PG-Limiter/v1.7.1/pg-limiter.sh -o /tmp/pg-limiter-v1.7.1.sh
sudo bash /tmp/pg-limiter-v1.7.1.sh update
```

An active private trial uses its recorded trial upgrade/rollback procedure instead of the installed update command. Its image, Compose files and persistent mounts must remain paired.

Release image: `ghcr.io/javadmoqaddam/pg-limiter:1.7.1`, for amd64 and arm64. The publication workflow also updates `:latest`.

## Interpretation and limits

- A successful HTTP request is not proof of complete per-user node evidence. Progress completion and lookup success are reported separately from enforcement coverage.
- API Per Device uses the panel's shared API inbound label. The IP endpoint does not expose real inbound tags or physical device identities.
- The panel's two-minute online window selects candidates; Last seen controls the applicable observation checks. API fallback to Logs after unsuccessful cycles remains configurable.
- Upstream HTTP 500s or malformed pages can still prevent a collection. No guard is bypassed to make an unavailable response appear successful.

See [API collection behavior](../API_IP_SOURCE.md) and [Logs readiness](../LOG_SOURCE.md) for details.
